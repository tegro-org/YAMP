# Phase 0 — Fork identity

Status: **approved 2026-11-10; implemented on branch `feature/phase-0-fork-identity`, awaiting the user's test
on the phone** (install next to the upstream app, play, Settings → About, check for updates). Part of
[multi-source-player.md](multi-source-player.md) (Phase 0). No feature work in this phase.

## Purpose

Make the app YAMP's own so a build can be installed next to the upstream app, updates itself from our
releases and never from upstream's, and is signed with our key. Until this is done **no YAMP build may be
released** (it would offer to "update" itself to Yandex Music Lite).

## What changes for the user

- A separate app "YAMP" with its own icon ("Rings"); the upstream app can stay installed alongside.
- Versions come from git (D37): the first release tag is **v0.1.0**; upstream's 1.12.2 / 47 numbering ends here.
- Settings → About shows YAMP, links to `tegro-org/YAMP`, the GPL-3.0 licence and the upstream attribution.
- Everything else looks and behaves exactly as upstream 1.12.2.

## Technical design

### 1. Identity (D16)

| Item | From | To |
|---|---|---|
| Kotlin package (188 files + tests) | `com.korenskoy.yandexmusic` | `org.tegro.yamp` — directories moved, `package`/`import` lines rewritten mechanically |
| `namespace` (app, baselineprofile) | `com.korenskoy.yandexmusic[.baselineprofile]` | `org.tegro.yamp[.baselineprofile]` |
| `applicationId` | `YandexMusicLite.KorenskoyR` | `org.tegro.yamp` |
| `app_name` + 6 strings naming the app | "Yandex Music Lite" | "YAMP" |
| Wake-lock tags, widget action names | `YandexMusicLite…` | `yamp…` |
| Launcher icon | upstream's note glyph | YAMP's own: the "Rings" mark (two source arcs around a play knob), sources in `Design/icons/`, generated by `Design/icons/make-launcher-icons.sh` (adaptive foreground + monochrome + legacy PNGs). "Three rings" is the alternative, one command away |

Manifest authorities already use `${applicationId}`; backup/extraction rules, notification channels and the
Keystore alias (`auth_secure`) need no change. Yandex `client_id`, User-Agent and `YANDEX_SALT` stay as they are
(unofficial client, see `kb/privacy-audit.md`).

### 1a. Version from git (D37)

`build.gradle.kts` derives both numbers; nothing in the file is bumped by hand any more:

- `versionName` = the last tag without the `v` for a build exactly on a tag (release), otherwise
  `<tag>-dev.<commits since the tag>+<short sha>`, e.g. `0.1.0-dev.12+a7fd9d8` (debug / untagged).
- `versionCode` = the number of commits on the branch (`git rev-list --count HEAD`) — monotonic, so the
  updater's "higher code wins" rule holds by itself.
- Fallback without git (e.g. a source archive): `0.0.0-local` / `1`.
- Releasing = creating the tag `v<major.minor.patch>` (the user chooses the number) and pushing it; the release
  workflow builds from the tag. `scripts/build-apk.sh` names the APK after the derived `versionName`.

### 2. Updater (D14)

`GitHubUpdateManager`: `repoOwner = "tegro-org"`, `repoName = "YAMP"`, User-Agent `YAMP-Android`, temp/target
file names `YAMP…`. Host allow-list (`github.com`, `*.githubusercontent.com`), SHA-256 digest check and
same-signer check stay. `SettingsSheet` source/licence links → `tegro-org/YAMP`.
The updater takes the first `*.apk` asset of the latest release and its digest, so the release workflow must
upload exactly one APK, named `YAMP-<version>.apk`.

### 3. Signing key

- The user creates the key once, **outside the repository**, and backs it up:
  `keytool -genkeypair -v -keystore yamp-release.jks -alias yamp -keyalg RSA -keysize 4096 -validity 36500`
- Locally: `KEYSTORE_FILE`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` in `android/local.properties`
  (git-ignored, as are `*.jks` / `*.keystore`).
- CI: secrets `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`; the workflow decodes the
  keystore into `android/` at build time only.
- Debug builds keep upstream's behaviour (use the release key if present), so a locally signed debug build
  can be updated by CI releases.

### 4. CI (`.github/` at the repo root, from `kb/upstream/github-workflows-reference/`)

- `ci.yml` — push to `main` / PR: gitleaks; JDK 21; `working-directory: android`; `chmod +x gradlew`;
  `verifyRoborazziDebug lintDebug`; upload screenshot diffs on failure.
- `release.yml` — tag `v*`: keystore from secrets, unit tests, `assembleRelease`, APK content check (no key
  material inside), GitHub release with the single APK. The version is derived from the tag (§1a), so the
  old "tag equals versionName" guard becomes a check that the build is on a tag.
- `dependabot.yml` — gradle `directory: /android`, actions monthly.

### 5. Tests and guards (I3: updated, not deleted)

- `LayoutSafetyTest`: `app_name == "YAMP"`, `applicationId == "org.tegro.yamp"`, changelog fixture URL.
- `ExampleInstrumentedTest` package name; `BaselineProfileGenerator.PACKAGE`.
- `UpdateUrlTest`, `UpdateRequestsTest`: `tegro-org/YAMP` URLs, `YAMP-Android` User-Agent.
- `ArchitectureTest` text scans: package root string.
- Screenshot goldens that show the app name (Settings → About and any update/crash dialogs): re-record with
  `recordRoborazziDebug`, review the diffs, commit the new PNGs. Everything else must stay pixel-identical.

### 6. Docs

- `README.md`: YAMP description, attribution to upstream (kept), GPL-3.0.
- `kb/upstream-tracking.md`: porting note — upstream paths `com/korenskoy/yandexmusic/` map to
  `org/tegro/yamp/`; identity strings/constants are never ported.
- `kb/architecture/build-and-ci.md`: new identity, CI, secrets.
- Privacy checklist (`kb/privacy-audit.md`, J3) re-run for the updater change: same hosts, new repo.

## Order of work and verification

1. Package move + namespace + applicationId + strings (one commit, mechanical).
2. Updater, settings links, wake-lock/widget tags, tests and guards (one commit).
3. `sh gradlew assembleDebug testDebugUnitTest verifyRoborazziDebug lintDebug` — all green; re-record only the
   goldens that legitimately changed.
4. Install the debug APK on the phone next to the upstream app: both run; YAMP plays; Settings → About shows
   YAMP; "Check for updates" reports no update (no release yet) and never offers an upstream APK.
5. CI workflows + README + KB (one commit). First CI run on push; first tag `v0.1.0` only when the user says so.

## Risks and side effects

- **Upstream ports get a path mapping** from now on (accepted in D16).
- **The app is new to Android:** nothing from an installed upstream app (accounts, downloads) carries over.
  Fine — there are no YAMP users yet.
- **Baseline profile** must be regenerated for the new package (needs a device; can wait).
- **Device-code sign-in** needs `YANDEX_DEVICE_SECRET` at build time, which upstream keeps out of the repo.
  Without it the code sign-in is disabled and only the WebView sign-in remains — see open question 2.
