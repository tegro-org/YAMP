# Product decisions

Decided with the user on 2026-11-08/09 (design discussion before the repo existed). Detailed design:
`docs/multi-source-player.md`.

| # | Decision | Why |
|---|---|---|
| D1 | Hard fork of upstream YandexMusicLite, not of YML; no merges, manual porting | Upstream is the active source and has fixes YML lacks; rework is too deep for merges |
| D2 | Own standalone repo `tegro-org/YAMP` (not a GitHub fork), code in `android/`, with `docs/`, `kb/` and `Design/` next to it | Fork network limits; room for docs/kb/design next to the app |
| D3 | Name **YAMP** (Yet Another Music Player); name clashes exist (hobby projects) but are irrelevant for a personal app with a unique `applicationId` | Nod to YML |
| D4 | Jellyfin first; Subsonic/Airsonic deferred and likely dropped | Jellyfin is more modern; Airsonic only served as a 2nd-queue workaround |
| D5 | No de-duplication between Jellyfin and Airsonic | Jellyfin is primary |
| D6 | Multiple persistent queues (Musicolet-style) — the key feature; queue must never be lost on process death | Main reason for the project |
| D7 | ~~Queues follow the Yandex account logic (per account)~~ — **superseded by D22** | — |
| D8 | Playing an album/folder replaces the active queue; queue switching via a popup from a queue button (home, player, car) — no full-screen queue manager | Simple; Musicolet's screen is overkill |
| D9 | Radio/mixes follow YouTube Music: generated list is persistent (go back/forward); re-run = new queue | User preference |
| D10 | Jellyfin radio = Instant Mix first | Never tried; evaluate before building alternatives |
| D11 | Favorites per provider, native semantics (Yandex likes incl. albums/artists; Jellyfin `IsFavorite`) | Each service has its own |
| D12 | Folder browsing on Jellyfin is first-class; ≤ 3 taps to any folder, 1 tap to pinned/recent | Library is organised by folders; Symfonium too slow |
| D13 | Jellyfin over HTTPS only | Security; no cleartext exceptions |
| D14 | Updates from `tegro-org/YAMP` GitHub Releases; own `applicationId` + signing key | Independence from upstream update channel |
| D15 | Don't decompile closed-source players (Musicolet, Symfonium) | Not needed, licensing |
| D16 | Package + `applicationId` `org.tegro.yamp`, renamed once in Phase 0 — **`applicationId` revised by D55** (the Kotlin package stays) | Own identity; tegro.org domain |
| D17 | Gradual Gradle module split: new code in modules (`:core:domain`, `:provider:jellyfin`…), Yandex code moves out after wrapping | Compiler-enforced boundaries, faster builds, without a big move |
| D18 | Proper Navigation Compose graph inside `main` (replaces in-VM catalog stack), at the latest with the folder browser | Current hand-built frame doesn't scale to new screens |
| D19 | Several providers signed in at once; UI sections shown per capabilities of the configured providers; upstream extras (FM radio, charts, My Wave) kept | User idea 2026-11-09 |
| D20 | Full localization: English default + Russian, more later; semantic keys; in-app language choice; existing strings migrated in one pass | Proper i18n, gradual like the rest |
| D21 | Search across providers: one merged result list with provider badges | User choice |
| D22 | Queues are app-wide (not per account); entries of a signed-out provider shown unavailable and skipped; My Wave, likes, Yandex playlists stay per account — **revised by D22′** (Phase 2a: every queue has an owner account) | Yandex has no named multi-queue concept; account-bound queues would hide queues on account switch and fail with Jellyfin-only |
| D23 | Phone is a first-class target, equal to the car head unit — YAMP is not a car-only app. The current Hi-Fi look on the phone (glass, iOS-like buttons) is liked and kept as the visual reference | User uses the app on the phone daily (tested 2026-11-09) |
| D24 | `ARCHITECTURE.md` and `DESIGN_GUIDE.md` approved; their rules are binding | User review 2026-11-09 |
| D25 | Local files (music stored on the device) will be supported as another provider. Only planned: scanning, index storage and track identity are **not decided** and are discussed when that phase starts (`docs/multi-source-player.md` Phase 4d) | User request 2026-11-09; keep the provider abstraction free of server/account assumptions |
| D26 | Queue switching uses the popup everywhere, the car included: 2 taps (open, pick). No queue tiles on car home; the 1-tap car budget stays for pinned/recent folders only | Switching is done once when getting into the car, not repeatedly (user, 2026-11-09) |
| D27 | One reference form for every provider item: `<provider>:<kind>:<id>` with a word for the kind (`yandex:track:12345`, `yandex:album:123`, `jellyfin:folder:…`), tracks included; split at the first two colons, the rest is the provider's id. One server per provider type for now | Letter prefixes glued to the id are ambiguous (Jellyfin ids are hex), ids may contain colons, one parser for seeds/pins/navigation/Android Auto (ARCHITECTURE C1) |
| D28 | `docs/multi-source-player.md` approved as the feature plan (phases 0–6) | User review 2026-11-09 |
| D29 | Re-running a saved mix replaces that mix's previous queue (amends D9 for mixes; whether radio re-run also replaces is still open) | Otherwise queues pile up (user, 2026-11-10) |
| D30 | A queue may mix providers freely (no "one account per queue" rule). Favourites stay per provider and are not merged into one list; where a single button must act alone (Library Play / Shuffle, the car "Liked" tile) it uses the **first source in the Sources list** | Mixed queues cost nothing in the architecture; a merged "Liked" needs an order rule and plays duplicates (user, 2026-11-10) |
| D31 | Jellyfin sign-in also offers **Quick Connect** (a code shown on the device, confirmed from a signed-in Jellyfin client) as an alternative to user name + password; the password form stays | No password typed on the head unit; same idea as the existing Yandex code sign-in (user, 2026-11-10) |
| D32 | "Driving" = car mode: big targets, never requires typing. "Parked" = the normal landscape interface, where typing lives. No motion detection, nothing is blocked; car mode has a search button that opens the landscape search in one tap. To be tried on the unit and adjusted from feedback | The user wants to be able to search by typing while driving; safety comes from car mode not needing it, not from blocking (user, 2026-11-10) |
| D33 | Car tiles are one priority list — Folders, My Wave, Liked, Mixes, Radio — shown as many as fit (the row scrolls for the rest); a tile exists only while a source supports it. **No Offline tile and no "Downloaded" row in Library:** downloaded music is offered where it is needed — the weak-signal pill in car mode and the offline state of a list play it — and is browsed and managed under Settings → Storage ("Available offline"). On the phone FM radio stays a tab, so Library has no Radio row | Offline is a specific, rare use case that the app mostly handles by itself; the tile row must also fit the split panes (user, 2026-11-10) |
| D34 | "Play downloaded" in an offline list plays the downloaded part of what is open (the current list, queue or wave), not everything on the device; everything downloaded is browsed under Settings → Storage | The two sets differ (user, 2026-11-10) |
| D35 | Queues are bounded by kind: the user's own queues are never touched automatically; My Wave is one per Yandex account; **one radio queue at a time** — starting another radio replaces it, "Keep" copies it into a named queue of the user's; one queue per saved mix (re-run replaces, D29) and a single "Last mix" queue for unsaved builds. Replaces the "keep last N radios" pruning. *Revised by D35′ (Phase 2): many radios, "Keep" no longer copies* | Otherwise radios and mixes pile up in the queues sheet; the user can always make a new queue when wanted (user, 2026-11-10) |
| D36 | Stream quality: resolve the variants in parallel, start with the one the link can carry (MP3 on a weak link), upgrade to lossless from the next track on; the next track is prepared as early as the current track's buffer and the link allow (not at a fixed point), so most skips are crossfades; a manual skip stops the current track at once with a loading state; recovery retries at a lower quality before giving up. No mid-track stream switching | Both phone problems of 2026-11-10 (skip "hang", FLAC never downgraded); mid-track switching is audible and doubles data (user, 2026-11-10) |
| D37 | Versions are derived from git, never bumped by hand: a release build on tag `vX.Y.Z` is `X.Y.Z`; any other build is `<last tag>-dev.<commits>+<sha>`; `versionCode` = commit count. Releasing = the user creates and pushes the tag (minor for features, patch for fixes). First YAMP tag v0.1.0 | Builds must not edit source files; the installed debug build must say exactly what it is (user, 2026-11-10) |
| D38 | Player findings 1–3 are **not** part of Phase 1: one audio session per player + manual skip as quick fade with a loading glyph go into a separate fix branch (next patch release) *before* Phase 1 code; D36's parallel resolution / quality ladder gets its own design doc | Engine work mixed into the queue restructure makes the phone test ambiguous (user, 2026-11-10, `docs/phase-1-queues.md` Q1) |
| D39 | A new queue repeats **All** by default (a finished queue starts over, as today); Off / One selectable per queue | Keeps today's behaviour (Q2) |
| D40 | In Phase 1 "wave by track" stays inside the My Wave queue (station switch with undo, seed persisted); Phase 2 turns it into the Radio queue. *As built in Phase 2: wave by track stays on My Wave; off the wave the same controls start a radio (D53, D54)* | Limits Phase 1 scope (Q3) |
| D41 | FM radio is a **live-station mode beside the queues**, not a queue: the active queue stays frozen while a station plays; restore shows the station as today | A station has no entries or cursor (Q4) |
| D42 | Deleting the active queue is allowed (confirmation dialog); the next queue in the list becomes active, paused; if none is left, My Wave | (Q5) |
| D43 | "Save as playlist" from the queue menu is deferred to Phase 5 (playlist edit per provider) | (Q6) |
| D44 | "Add to end of queue" / "Add to queue…" exist at track level **and** on album / playlist headers for the whole list | Building a queue from several albums is the main use case (Q7) |
| D45 | ~~Per-player audio sessions are a **setting** (Settings → Playback → "Separate audio sessions", off by default): the phone keeps the shared session (system equalizer shapes the crossfade as one), the head unit switches it on; both sessions are announced to the equalizer~~ — **retired 2026-11-16 by D70** (one stable session for both players; the setting is removed) | A per-install switch lets each device keep what works and A/B the unit without a rebuild (user, 2026-11-10, `docs/player-skip-and-audio-session.md`) |
| D46 | **History**: every track start is recorded app-wide and browsable in Library ("History", by day, with track actions) — Phase 1b, right after Phase 1 | A good track skipped past once was otherwise never found again (user, 2026-11-11) |
| D47 | **Unavailable storage never empties a queue or the library.** A removable source (USB stick, SD card) mounts late after the head unit's cold boot; entries that point to it stay in the queue as unavailable and are skipped, the local-files index is kept, and both come back when the storage appears — nothing is pruned or re-scanned away because a source is missing at start-up. Storage-side twin of D22 | Musicolet lost the queue and the library when the USB stick was not yet mounted at cold boot (user, 2026-11-11) |
| D48 | **Diagnostic log file** on the device (About → switch "Диагностический журнал", default on in debug / off in release, Share + Clear), written through by the playback journal, recovery, service, focus, errors and the crash handler; secrets scrubbed | Nobody brings a laptop into the car for `adb logcat`; the in-memory journal dies with the DPI tool's kill (user, 2026-11-11, `docs/diagnostic-log.md`) |
| D49 | The first tab follows the **active queue** (name, knob, "Дальше"); wave-only controls appear only while the wave queue is active; My Wave is reached through the switcher or the car tile | The wave page's knob and pills switched the user away from the queue they chose (head unit, 2026-11-12) |
| D50 | **History is one list filtered by queue**, the active queue selected by default; rows keep `queueId` + a name snapshot | Queues are separate spaces, History follows them (user, 2026-11-12) |
| D35′ | **Revises D35:** the user's own queues are never touched automatically; My Wave is one per Yandex account; **radios are as many as the user starts** — "Start radio" offers re-seeding an existing radio or a new one; one queue per saved mix (re-run replaces, D29) and a single "Last mix" for unsaved builds. "Keep copies the radio into a named queue" is dropped | One radio per purpose, each resuming where it stopped; re-seeding in place keeps the list from piling up (user, 2026-11-13, `docs/phase-2-radio.md`) |
| D51 | **"Start radio" picks the target**: an existing radio (re-seeded, no confirmation) or a new radio; normal queues are never a target. Same picker on phone and head unit | Radios are disposable, user queues are not (D35′); a short list is fine in the car (D26) |
| D52 | **Keep** is a per-radio flag that means *retain history* and nothing else: off → the played head is dropped at the next refill (3 tracks behind the cursor stay); on → everything stays; switchable any time (start sheet, queue long-press menu); only on `RADIO` queues. Any radio stays re-seedable regardless | Back/forward over a long session when wanted, a short queue sheet when not (user, 2026-11-13) |
| D53 | **My Wave is not touched in Phase 2**: `WaveQueue` and its own list stay; the radio gets its own `DynamicSource` (`RotorStationSource`). Merging the wave into the radio model, and retiring `WaveQueue`'s list, is a later step | The wave works on the unit today; one moving part at a time (user, 2026-11-13) |
| D54 | **Wave controls follow the active queue**: on the `WAVE` queue they are wave-internal (D40), on any other queue each becomes its radio equivalent ("Start radio" → picker); wave-only controls (tuning, "back to My Wave") have no equivalent and stay hidden off the wave (D49) — **"Start radio" in the track menu revised by D65** | One control per place, its meaning given by the queue the user is in (user, 2026-11-13) |
| D55 | **`applicationId` is `org.tegro.music.yamp`** (revises D16's id; `namespace` and the Kotlin package stay `org.tegro.yamp`, internal action strings unchanged). A one-time reinstall: it is a new app to Android — data, sign-ins and permissions start over; the old app's updater refuses the new package | Head-unit "now playing" apps filter players by package name: "Заставка Home" accepts only names containing `music`/`audio`/`media`/`player`/`radio`/`podcast` or a fixed list, so `org.tegro.yamp` was ignored (found 2026-11-14); done while the user base is tiny |
| D22′ | **Revised:** queues stay app-wide *in visibility* — the queues of every signed-in account are shown, none hidden by a switch — and each has an owner account (D57); a signed-out account's queues are kept, collapsed (D62), their entries unavailable and skipped | D22's reason (nothing hides on a switch) holds; ownership is new |
| D56 | **All signed-in accounts are live at once; no global account switch.** The active queue's account is the context for Home, Library, Search and likes. Upstream's switcher and startup picker retire; Settings keeps add / remove / default | Taste separation needs several accounts used side by side; a switch that stops playback and reloads everything is the opposite (user, 2026-11-14) |
| D57 | **Every queue is bound to one account at creation** (`PlayQueue.account`, normal and radio; WAVE as today). Streaming, likes, radio refill and feedback use the queue's account. Default = the active queue's account; permanent (D61) | A queue plays, refills and reports under one taste (user, 2026-11-14) |
| D58 | **Selectors and markers only with more than one account**; with one account the UI is unchanged | No extra controls without a reason (user, 2026-11-14) |
| D59 | **Accounts are keyed by the Yandex uid**, not by the login-based folder name; `owner` / `account` columns and per-account stores are migrated | `folderName` (login → display name → uid) can collide and changes when a provisional `temp_` account learns its details (`UserAccount.kt:27`) |
| D60 | **One network client per account** (`ProviderAccount` + per-account OkHttp/Retrofit sharing one connection pool, own HTTP cache directory); a call names its account explicitly or takes the context account | No token ever crosses accounts, cached answers stay per account; the same shape Phase 3 needs for every provider (C5, C6) |
| D61 | **The binding is permanent**: a queue's account is set at creation and never changed (no "change account" action anywhere); re-seeding a radio keeps it | A queue's history and suggestions belong to one taste; moving it would mix them (user, 2026-11-14) |
| D62 | **Sign-out hides, it doesn't delete**: the account's queues (incl. its My Wave) are kept and shown only in a collapsed "Removed accounts · N" group at the bottom of the phone switcher (Delete only); not in the car or Android Auto; signing back in to the same uid restores them. Cached lists and unshared downloads are removed | Nothing the user built is lost by a sign-out; the everyday list stays clean (user, 2026-11-14) |
| D63 | **Every Yandex account's My Wave queue exists from sign-in** (and from the migration for already signed-in accounts): created empty at once, filled on first activation; the account's default queue and its entry point in the switcher, car and Android Auto. Re-sign-in of a removed account (same uid) brings back its old WAVE queue with its position (D62), no new one. Today it is created lazily (`PlaybackController.resetForAccount` → `QueueManager.waveQueue`, `QueueManager.kt:224`, only on switch/play) | With no global switch, a queue of the account is the only way into it; My Wave is the natural one (user, 2026-11-14) |
| D64 | **Queue list: manual order, grouped by account by default.** `sortOrder` stays (new queues last, no "recently used" sort). "Group" (RU «Группировать») (Settings → Accounts, only with >1 account, default on): on = a section per account (header avatar + name; its My Wave first, then its queues in manual order; no row markers; reorder within a group); off = one flat list with a marker on every row. Car and Android Auto follow it (AA: a sub-folder per account); the car pill always shows the marker with >1 account. One account: no setting, no headers, no markers | Which account a queue plays under must be visible at a glance without cluttering every row (user, 2026-11-14) |
| D65 | **Revises D54 for the track menu:** "Start radio" (RU «Запустить радио») is in the track context menu on **every** queue, next to "Add to queue", and opens the usual radio picker (new radio or re-seed, with the account selector, D57); on the My Wave queue "Wave by track" stays as its own row above. The other D54 controls (player button, car pill) are unchanged | On My Wave the menu offered only "Wave by track", so a radio from a search result needed a detour through a new queue (user, 2026-11-15) |
| D66 | **Resume after a focus loss when nothing else plays** ("Продолжать, если ничего не играет", default on; **default off since D88**): only if YAMP was playing at the loss and the user hasn't touched playback since; never during a call; at most 3 resumes a minute | Poweramp Equalizer's session-close "Fade" takes focus for ~1 s and the head unit turns it into a permanent loss (2026-11-16) |
| D67 | **Keep loading until the user stops**: a pick or the current track keeps loading while data arrives; 20 s with no data pauses (with the reason in the journal); slowness never skips, only hard errors do | User's rule (2026-11-16): the player must not give up on a slow link |
| D68 | **One player for normal playback**: the next track plays gaplessly on the same AudioTrack (crossfade off); the second player only for a crossfade or a pick, then paused and cleared — never left to run dry or rebuilt as a silent standby | AudioTrack rebuilds caused the skip stutter and triggered the equalizer (2026-11-16) |
| D69 | **Fixed output format** (switch, default off; **always on, switch removed — D88**): both players resample to the mixer's native rate, 16-bit stereo | The unit's mixer runs at 48 kHz and every track is 44.1 kHz; A/B on the unit |
| D70 | **One stable audio session** for both players; one OPEN / CLOSE to equalizers ("Separate audio sessions" retired, D45) | The equalizer fades — and steals focus — when a session it equalizes closes |
| D71 | **`:core:domain`** (pure Kotlin/JVM): refs, models, accounts, provider / stream / outcome interfaces, queue model; Yandex in `:app` under `data/provider/yandex/`; Jellyfin in `:provider:jellyfin` | Phase 3: one neutral model before the second provider (docs/phase-3-providers.md) |
| D72 | **Caches are provider-private**: Yandex keeps `tracks` / `list_items`; each Jellyfin account has its own Room database; queues and History keep refs + display fields (no migration) | Accounts and providers stay independent; sign-out drops one account's data only |
| D73 | **Provider calls return `Outcome<T>` / `ProviderError`**; repositories may throw inside, the provider maps once | Errors don't cross the provider boundary |
| D74 | **The controller resolves streams**; the engine plays a `ResolvedStream` and never calls a resolver | One place for links, retries, cache keys and per-account routing |
| D75 | **Composition in a stable provider order**; with one provider the UI is unchanged; provider badges only with ≥ 2 providers | No visible change for Yandex-only users |
| D76 | **FM radio is a built-in, account-less source** | It belongs to no provider account |
| D77 | **`ArchitectureTest` guards the layers**: no Yandex DTO outside `data/provider/yandex/` (allow-list that only shrinks — now empty); `:provider:jellyfin` depends on `:core:domain` only | Keeps the refactor from sliding back |
| D78 | **A Jellyfin account = server + user** (`jellyfin:<serverId>/<userId>`); a duplicate sign-in is refused; refs name the server (`jellyfin@<serverId>:<kind>:<itemId>`) | Several servers side by side; one identity per server user |
| D79 | **Jellyfin streams via `/Audio/{id}/universal`** (codecs, max bitrate, max sample rate = mixer rate); the token only in a header, only to its server; covers via `Images/Primary` with size and tag | No token in URLs or logs; the unit's mixer rate respected |
| D80 | **Early preload**: the next track is resolved and prepared soon after the current one starts (not during a skip burst); its state (ready / loading / failed) is part of the player state | Next is instant; the state feeds D81 |
| D81 | **Next is never disabled**: loading = ring, failed = dimmed + badge; the whole button / car artwork is the tap target and retries under load-first (D67); a failed next track retries itself with a fresh link on `LINK → GOOD`; progress bars show the buffered part | The original app silently disables Next and can stay stuck (user, 2026-11-14) |
| D82 | **The existing pure domain code moved into `:core:domain`** in step 1 | Compiler-enforced purity from the start |
| D83 | **A Jellyfin account gets an empty default queue at sign-in** (its entry point in the switcher, like D63); re-sign-in restores its queues (D62) | The account is reachable at once |
| D84 | **A queue holds tracks of its own account only**: "Add to queue" offers only the track's account's queues; entries resolve through their queue's account. Multi-source queues stay a future item | Keeps accounts' tastes and tokens apart (D57) |
| D85 | **Development tests run against a local Jellyfin in Docker** with free test music (`scripts/jellyfin-dev/`, no secrets); the user's server only for the user | Nothing private near the public repo |
| D86 | **On-disk stream cache** (`SimpleCache`, LRU, key = account + track + quality, size in Settings, default 500 MB, separate from downloads); the next track written fully in the background, the previous one stays | Instant back / next, dropouts covered, FLAC on weak links |
| D87 | **Jellyfin play reporting**: `/Sessions/Playing`, `…/Progress` (every 10 s, on pause / resume with `EventName`, on seek) and `…/Stopped` under the playing queue's account; fire-and-forget, a failure is one journal line | The server's "now playing", play counts and resume positions follow YAMP (step 26) |
| D88 | **Playback settings cleanup** (2026-11-18): removed "Keep both players running" and "Keep audio streams" (no silent idling or parking — the engine runs as with both off), the "Announce to equalizer" switch (always one OPEN / CLOSE per session, D70) and the "Fixed output format" switch (always the mixer rate, D69); "Resume when nothing plays" (D66) and "Keep playing under announcements" stay, both **off by default** for new installs (stored choices kept) | The causes they worked around are fixed (Poweramp's Fade on a closing session → D70; overlapping players → handover rules, b110); the user wants fewer, meaningful settings |
